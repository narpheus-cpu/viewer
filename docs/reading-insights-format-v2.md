# 독서정보 통합 TXT 규격 v2 — 뷰어 구현 계약

## 1. 파일 구성
기존 TXT 본문은 원래 텍스트 그대로 둔다. 뒤에만 빈 줄 2개와 아래 데이터를 붙인다.

    [원문 전체]

    <<<READER_INSIGHTS_V2_BEGIN>>>
    {"schema_version":2,"records":[]}
    <<<READER_INSIGHTS_V2_END>>>

- 두 표식은 한 줄을 단독으로 차지한다.
- TXT를 불러올 때 맨 뒤의 두 표식이 정확히 있으면 본문과 JSON을 분리한다.
- EPUB은 기존 방식으로 그대로 읽으며 자동으로 정보를 생성하지 않는다.
- 일반 TXT에 표식이 없으면 본문으로만 읽고 독서정보는 자동 생성하지 않는다.
- 표식이 있는데 잘못된 JSON이면 본문에 노출하지 않고 오류를 반환한다.
- 원문에 우연히 표식이 포함되어도 맨 끝에 유효한 JSON과 종료 표식이 없으면 정상 통합본으로 보지 않는다.

## 2. 레코드 필드
schema_version은 2.
records는 배열. 각 레코드는:
- id: 한 작품 안에서 유일
- category: event / relation / character / clue
- subject: 주로 해당 인물 또는 장소·물건의 명칭
- title: 패널의 제목
- text: 본문 설명
- confidence: fact / strong_inference / tentative
- evidence: 실제 원문에서 짧게 복사한 근거 구절
- reveal: {quote: 원문에 실제 있는 최소 20자 구절, occurrence: 1부터 시작하는 출현 순서}
- replaces: 과거 레코드 id 또는 null
- story_order: 사건의 극중 순서에만 쓰는 정수 또는 null

## 3. 공개 규칙
- reveal.quote의 마지막 글자에 도달해야 레코드가 공개된다.
- 사용자 페이지 번호가 아닌, 원문 텍스트를 기준으로 위치를 매칭한다.
- 원문 근거(evidence)가 reveal.quote보다 뒤에 있다면 해당 정보는 유효하지 않다.
- 반복 구절은 occurrence를 통해 정확히 위치를 정한다.
- 본문 렌더링에서 quote를 찾지 못하면 **미공개** 처리한다(늦게 공개하는 편이 스포일러보다 안전).
- 독자가 실제로 방문한 위치 중 가장 먼 지점을 저장한다. 앞 페이지로 돌아가도 이미 본 정보는 사라지지 않는다.
- 기존 내용에 대한 새 해석(replaces)은 예전 기록을 덮어쓰지 않는다. 해당 위치까지의 변화 이력을 함께 보존한다.

## 4. 표시 및 저장
- 화면상 범주는 사건 연표/인물 관계/인물별 분석/핵심 단서의 네 종류뿐이다.
- 정보 페이지는 세로 스크롤하지 않는다. 한 화면에 맞는 분량으로 분할하며 터치/이전/다음으로 넘긴다.
- 파일 정보가 없다면 모든 탭의 본문 영역은 **완전히 비어 있다**. 원문 자동 발췌나 차례 대체 표시도 없다.
- 통합 TXT는 원문 본문만 기존 최근 읽기/검색/페이지 캐시에 들어간다.
- 독서정보 JSON은 본문과 별도 저장소에 저장하며, 같은 본문의 재열기에서도 불러올 수 있다.
- 개별 JSON 업로드(기존 [정보 불러오기] 버튼)는 계속 지원한다.
- TXT 원문을 외부 서버에 전송하지 않는다.

## 5. 권장 검증
단순 TXT, 통합 TXT, 잘못된 JSON, 중복 구절 occurrence, 근거가 미래에만 나오는 경우, 페이지 레이아웃 변경, 브라우저 재시작/최근 파일 복원, 패널 키·터치 독립 동작을 검사한다.
