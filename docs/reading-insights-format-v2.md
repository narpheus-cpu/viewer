# 독서정보 통합 TXT 규격 v2 — 뷰어 구현 계약

## 1. 파일 구성
기존 TXT 본문은 원래 텍스트 그대로 둔다. 뒤에만 빈 줄 2개와 아래 데이터를 붙인다.

    [원문 전체]

    <<<READER_INSIGHTS_V2_BEGIN>>>
    {"schema_version":2,"records":[]}
    <<<READER_INSIGHTS_V2_END>>>

- 두 표식은 한 줄을 단독으로 차지한다.
- TXT를 불러올 때 맨 뒤의 두 표식이 정확히 있으면 본문과 JSON을 분리한다.
- EPUB은 기존 방식으로 그대로 읽으며 자동으로 정보를 생성하지 않는다.
- 일반 TXT에 표식이 없으면 본문으로만 읽고 독서정보는 자동 생성하지 않는다.
- 표식이 있는데 잘못된 JSON이면 본문에 노출하지 않고 오류를 반환한다.
- 원문에 우연히 표식이 포함되어도 맨 끝에 유효한 JSON과 종료 표식이 없으면 정상 통합본으로 보지 않는다.

## 2. 레코드 필드
schema_version은 2.
records는 배열. 각 레코드는:
- id: 한 작품 안에서 유일
- category: event / relation / character / clue
- subject: 주로 해당 인물 또는 장소·물건의 명칭
- title: 패널의 제목
- text: 본문 설명
- confidence: fact / strong_inference / tentative
- evidence: 실제 원문에서 짧게 복사한 근거 구절
- reveal: {quote: 원문에 실제 있는 최소 20자 구절, occurrence: 1부터 시작하는 출현 순서}
- replaces: 과거 레코드 id 또는 null
- story_order: 사건의 극중 순서에만 쓰는 정수 또는 null

## 3. 공개 규칙
- reveal.quote의 마지막 글자에 도달해야 레코드가 공개된다.
- 사용자 페이지 번호가 아닌, 원문 텍스트를 기준으로 위치를 매칭한다.
- 원문 근거(evidence)가 reveal.quote보다 뒤에 있다면 해당 정보는 유효하지 않다.
- 반복 구절은 occurrence를 통해 정확히 위치를 정한다.
- 본문 렌더링에서 quote를 찾지 못하면 **미공개** 처리한다(늦게 공개하는 편이 스포일러보다 안전).
- 독자가 실제로 방문한 위치 중 가장 먼 지점을 저장한다. 앞 페이지로 돌아가도 이미 본 정보는 사라지지 않는다.
- 기존 내용에 대한 새 해석(replaces)은 예전 기록을 덮어쓰지 않는다. 해당 위치까지의 변화 이력을 함께 보존한다.

## 4. 표시 및 저장
- 화면상 범주는 사건 연표/인물 관계/인물별 분석/핵심 단서의 네 종류뿐이다.
- 정보 페이지는 세로 스크롤하지 않는다. 한 화면에 맞는 분량으로 분할하며 터치/이전/다음으로 넘긴다.
- 파일 정보가 없다면 모든 탭의 본문 영역은 **완전히 비어 있다**. 원문 자동 발췌나 차례 대체 표시도 없다.
- 통합 TXT는 원문 본문만 기존 최근 읽기/검색/페이지 캐시에 들어간다.
- 독서정보 JSON은 본문과 별도 저장소에 저장하며, 같은 본문의 재열기에서도 불러올 수 있다.
- 개별 JSON 업로드(기존 [정보 불러오기] 버튼)는 계속 지원한다.
- TXT 원문을 외부 서버에 전송하지 않는다.

## 5. 권장 검증
단순 TXT, 통합 TXT, 잘못된 JSON, 중복 구절 occurrence, 근거가 미래에만 나오는 경우, 페이지 레이아웃 변경, 브라우저 재시작/최근 파일 복원, 패널 키·터치 독립 동작을 검사한다.

## 6. 장편 원문을 안전하게 묶기
원본 TXT를 다시 출력하는 방식은 긴 파일에서 누락 위험이 있다. ChatGPT 프로젝트는 JSON을 생성한 뒤 원본 파일 바이트와 병합해야 한다. 도구 제공: tools/pack-reader-insights-v2.py (원본 TXT, JSON, 출력 TXT 순서로 입력). 웹 뷰어는 기존 textarea 동작에 맞춰 Windows CRLF를 LF로 정규화하여 화면에 표시한다. 파일 생성기는 원래 TXT 바이트를 그대로 보존한다.

## 7. 읽은 범위 계산과 수동 수정 (v3)
- 새 책은 처음에 읽음 0%다. 처음 열린 **첫 본문 페이지**만 실제 보이는 페이지 끝까지 인정한다. 과거의 `ebookViewerInsightsSeenV2` 누적 기록은 잘못된 100%가 있을 수 있으므로 자동으로 이관하지 않는다.
- 이어서 앞으로 넘긴 **인접한 본문 페이지**만 자동 인정한다. 다음 페이지 시작점이 직전 승인 지점과 연속되어야 한다. 목차, 검색, 쪽번호 직접 이동이나 복원으로 멀리 열린 페이지는 읽은 범위를 늘리지 않는다.
- 독서정보 패널의 [읽은 지점 수정]을 누르면 수정 모드로 진입한다. 본문에서 실제 읽은 페이지로 이동해 표시된 [이 지점 지정]을 누른다. [이 페이지 끝으로 지정], [선택 문장 끝으로 지정], [처음부터 다시 읽음]을 선택할 수 있다.
- 수동 지정은 증가뿐 아니라 감소도 허용하며, 그 즉시 모든 정보 범주를 새 범위로 필터링한다. 수정 위치는 책 본문 식별자별로 `ebookViewerInsightsReadCursorV3`를 사용해 보존한다. 수동 수정 뒤 뒤쪽 페이지를 실수로 다시 열어도 자동으로 100%가 되지 않는다.
- 페이지 설정이 변경되어도 저장 기준은 **페이지 번호가 아닌 정규화된 본문 원문 오프셋**이다. 새로운 페이지의 끝이 본문에서 어디인지 변환한 뒤 기록한다. 읽은 문장 일부를 선택한 경우 선택 끝 위치까지 기록한다.

## 8. 단어 드래그 메뉴에서 읽은 지점 지정 (v4)
- GitHub 웹 뷰어의 본문 단어 또는 문장을 드래그/길게 눌러 선택하면 기존 ChatGPT 연결 옆에 [읽은 지점 지정]을 표시한다.
- 선택한 **단어의 마지막 글자 오프셋**을 읽은 지점으로 저장한다. 이때 현재 페이지의 끝까지 읽었다고 처리하지 않는다.
- 같은 단어가 페이지 안에 여러 번 등장하면 실제 DOM 선택 종료 위치에 가장 가까운 원문 위치에 대응시킨다. 위치를 확인할 수 없다면 임의로 저장하지 않고 오류 메시지를 출력한다.
- 누르는 즉시 읽은 범위를 늘리거나 줄이는 수동 교정을 실시하고 '이 페이지까지 읽은 지점으로 지정됨 · 선택한 단어 끝 기준'이라는 확인 메시지를 표시한다.
- 이후 **그 페이지부터 연속으로 앞으로 넘길 때** 다음 페이지의 끝 위치까지 자동 기록을 재개한다. 검색/목차/번호로 건너뛰는 이동은 여전히 자동 읽음 범위를 증가시키지 않는다.
- Android의 일반 웹브라우저에서는 운영체제 선택 메뉴에 항목을 삽입할 수 없으므로, 선택한 단어 부근에 웹페이지 자체 버튼을 띄운다. APK의 네이티브 텍스트 선택 메뉴는 별도의 앱 코드 변경이 필요하며 이 변경에는 포함되지 않는다.

## 9. 장편 탐색 내비게이터 (v5 시제품)

기존 독서정보 패널의 네 범주는 유지한다. 메타데이터가 있는 경우 첫 화면은 **독서정보 탐색**으로 열린다. 다음 경로는 스크롤 없는 목록 페이지를 사용한다.

- **지금 읽는 장면:** 본문에서 현재까지 읽은 위치, 레코드의 scene_id, 공개된 주요 대상 명칭·별칭을 기준으로 관련 기록 **최대 10건**을 추천한다. AI가 현재 장면의 의미를 새로 창작하는 기능은 아니다. 덮어써진 옛 판단은 기본 추천에서 제외한다.
- **인물 찾아가기:** 그 인물과 연결된 네 범주를 한곳에 모은다. 기본 화면에는 이미 수정된 판단을 제외한 **현재 상태**를 보여주고, [변화 이력]에서 모든 과거 판단을 열람한다.
- **사건 지도:** 공개된 주요 사건 목록을 story_order 우선으로 정렬한다. 순서가 불명확한 경우에는 공개 위치를 기준으로 한다.
- **핵심 단서:** 장소·사물·소재에 해당하는 명시적 엔터티로 바로 이동한다.
- **최근 변화:** 현재 읽은 범위 안에서 최근에 새로 드러나거나 수정된 기록을 역순으로 보여준다. 독서 시간대별 알림 기능은 아직 아니다.
- **통합 검색:** 공개된 레코드의 제목·주제·본문·근거 및 공개된 이름·별칭만 검색한다. 정교한 의미 검색이 아니라 정확한 문자열 기반 색인 검색이다.
- **전체 정보 보기:** 기존 사건 연표/인물 관계/인물별 분석/핵심 단서의 네 분류로 전환한다. 상단 [탐색]을 눌러 돌아올 수 있다.

본문을 드래그하면 기존 [ChatGPT연결] 및 [읽은 지점 지정]과 함께 [독서정보 보기]를 제공한다. 이 버튼은 선택한 단어를 **공개된 기록만** 대상으로 검색하며, 명확한 인물 이름·별칭 하나가 일치하면 그 인물의 현재 상태로 직접 이동한다.

독서정보 JSON의 기존 필드는 필수 그대로다. 다음 항목은 선택적 추가 메타데이터다.

- `entities`: 현재 공개 시점까지 알 수 있는 `{id,name,type,aliases}` 배열. type은 person/place/object/concept/other 중 하나.
- `aliases`: 핵심 대상의 공개된 별칭 배열.
- `scene_id`: 장·사건 혼합 분석으로 정한 장면 식별자.
- `related_ids`: 연관 레코드 ID 배열. 연결 상대가 아직 미공개라면 인터페이스는 보여주지 않는다.
- `importance`: 중요도 1~5, 기본값은 3.

이 메타데이터가 없는 구형 JSON도 subject/category/title을 이용한 기본 탐색이 가능하다. 특정 인물의 동일성이나 숨겨진 의도는 임의로 추론하여 연결하지 않는다.

**검증용 통합 소설:** `tests/fixtures/insights-navigator-demo.txt`. 24개 장면, 네 범주별 24건씩 총 96건이 들어 있는 기능 시험용 가상 소설. 해당 TXT를 뷰어에 열고 실제로 읽은 위치로 진행하거나 [읽은 지점 수정]으로 범위를 지정한 뒤 탐색 기능을 확인할 수 있다.

**APK 네이티브 선택 메뉴는 아직 변경하지 않았으며 웹 버전만 대상**이다. 키워드 검색, 패널 페이지 이동과 공개 위치의 소스 코드 및 단위 테스트가 적용되어 있으며, 실제 기기에서의 체감 성능은 별도 검증 대상이다.

## 10. 근거 문구 표시 요약 (v1.33)
- 모든 독서정보 범주(사건 연표, 인물 관계, 인물별 분석, 핵심 단서) 및 장편 내비게이터 상세 화면의 `근거:` 문구에 동일한 출력 규칙을 적용한다.
- 한 기록의 근거 원문을 **문장 단위**로 세어 총 6문장 이하라면 생략하지 않고 전문을 그대로 보여준다.
- 7문장 이상이라면 **처음 3문장 + (중략) + 마지막 3문장**만 표시한다. 예: `근거: 1문장. 2문장. 3문장. (중략) 12문장. 13문장. 14문장.`
- 근거 원문은 JSON/DB/원문 검증/검색 색인에 계속 전문을 보존한다. **화면 표시 단계에서만** 중간 문장을 줄인다. 문장 분리는 한국어 문장부호, 인용부호, 소수점 등을 고려한다.
- 긴 요약 근거도 전자잉크 화면에서는 기존처럼 내부 스크롤 없이 페이지로 나눠 표시한다.
