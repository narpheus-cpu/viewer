# 소설 독서정보 생성 프로젝트 — 프로젝트 지침 v2

## 최상위 목표
업로드된 소설을 처음 읽어 가는 독자가 **그 지점까지 드러난 사건·인물·관계·욕망·핵심 단서를 제대로 이해하도록** 돕는 독서정보를 만든다. 작품 요약, 사건의 기계적 열거, 정답 해설은 목표가 아니다.

**오직 사용자가 제공한 원문을 근거로 한다.** 외부 정보, 인터넷 검색, 작가 인터뷰, 영화, 기존 해설, 모델이 알고 있던 작품 전개를 이용하지 않는다. 소설 본문은 한 글자도 수정하거나 생략하지 않는다.

## 구간 설정과 분석
1. 챕터 경계와 **중요한 사건으로 인한 정보 변화**를 혼합하여 구간을 나눈다. 중요한 사건이 많은 장은 여러 구간으로 나누고, 변화가 없는 구간에는 억지로 정보를 추가하지 않는다.
2. 구간 i의 정보를 만들 때는 **해당 구간 끝까지의 원문과 이미 작성한 이전 구간 정보만** 사용한다. 가능한 경우 앞부분 원문만 제공하여 단계별 독립 분석한다. 후속 구간을 알고 있다는 이유로 미래 내용을 암시하거나 과거 장면을 소급 해석하지 않는다.
3. 이전 정보에 비해 독자의 이해를 바꾸는 사실과 해석만 추가한다. 중복을 피한다.
4. 사건의 **소설 속 실제 발생 순서**와 **독자에게 알려진 순서**를 구분한다. 회상이나 비선형 구성에서 사건의 순서가 불확실하면 임의로 확정하지 않는다.
5. 새로운 정보마다 실제 원문 근거와 **해당 정보가 처음 공개 가능한 마지막 원문 위치**를 기록한다. 페이지 번호는 글꼴·레이아웃에 따라 바뀌므로 쓰지 않는다.

## 네 가지 범주
- event / 사건 연표: 사건의 결과와 명확한 인과관계를 중심으로 중요한 사건만 기록한다. 사소한 동작, 배경 묘사, 문학적 분위기 변화는 제외한다.
- relation / 인물 관계: 주인공과 주요 인물 중심. 혈연·친교·조력·조직·갈등·경쟁 등을 객관적으로 드러난 관계와 인물의 주관적 믿음을 구분하며, 관계 변화의 이유를 설명한다. 엑스트라는 제외한다.
- character / 인물별 분석: 주요 인물의 겉으로 내세우는 목표와 내면의 욕망, 행동의 제약, 의도의 변화를 분석한다. 명시되지 않는 심리는 반드시 행동과 발언에 근거한 추론으로 표기한다. 근거가 부족하면 보류한다.
- clue / 핵심 단서: 인물 외의 중요한 사물·장소·감정·기억·반복 소재가 지금까지 가지는 의미를 설명한다. 미래 전개나 결말을 암시하지 않으며 단순한 소품은 제외한다.

## 분석 강도
- fact: 원문에서 명시적 또는 직접 확인할 수 있는 사실.
- strong_inference: 현재까지의 여러 관찰로 지지되는 강한 해석.
- tentative: 그럴듯하지만 아직 불확실한 가설. 꼭 필요할 때만 제한적으로 포함한다.
- 분석은 독자의 해석 여지를 남겨 둔다. 미래를 알고 쓰는 상징 해설, 결과를 예측한 단정, 원문에 없는 관계·동기 창작을 금한다.
- 변화가 일어나면 기존 내용을 지우지 말고 새 레코드를 만들고 replaces에 이전 ID를 넣는다. 이전 시점으로 돌아간 독자에게는 그 시점의 과거 판단만 보일 수 있어야 한다.

## 통합 TXT 산출물
최종 파일은 UTF-8 TXT 하나다. **본문을 언어모델로 다시 생성하지 않는다.** 원본 파일의 실제 바이트를 그대로 복사한 후 메타데이터만 파일 끝에 덧붙인다. 파일을 다룰 수 있는 실행 환경이라면 먼저 독서정보 JSON을 만든 뒤 제공된 tools/pack-reader-insights-v2.py를 실행해 병합한다. 별도 도구 없이 원문을 재출력하는 방식은 허용하지 않는다. 원문 끝에 개행 두 개를 추가하고 정확히 아래 형식으로 메타데이터를 붙인다.

시작 줄: <<<READER_INSIGHTS_V2_BEGIN>>>
다음 줄부터: JSON 객체
끝 줄: <<<READER_INSIGHTS_V2_END>>>

JSON 객체는 다음 필드를 갖는다.
- schema_version: 반드시 정수 2
- records: 배열. 중요 정보가 없는 경우 빈 배열 허용
- 각 항목 필수: id, category, title, text, confidence, evidence, reveal.quote, reveal.occurrence
- id: 작품 내 유일한 문자열(예 R0001)
- category: event / relation / character / clue 중 하나
- subject: 해당 인물, 관계쌍, 단서의 이름(사건은 생략 가능)
- title: 사람이 읽는 짧은 제목
- text: 해설 본문. 간결하면서도 인과·변화·정황을 읽을 수 있도록 작성
- confidence: fact / strong_inference / tentative 중 하나
- evidence: **실제 원문에서 정확히 복사한 짧은 인용문**, 해당 레코드의 주장에 대한 직접적인 근거
- reveal: quote, occurrence로 구성
- reveal.quote: 이 정보가 공개되어도 되는 마지막 지점의 원문에 실제 등장하는 **20자 이상의 정확한 구절**. 그 이전 내용만으로 정보를 뒷받침할 수 있어야 한다.
- reveal.occurrence: 같은 reveal.quote가 원문에 여러 번 등장하면 몇 번째인지 가리키는 1부터 시작하는 정수
- replaces: 대체·수정하는 앞선 기록의 ID 또는 null
- story_order: 사건의 극중 순서가 확실한 경우의 양의 정수, 아니면 null

예시 JSON 모양(의미 없는 자리 채움이며 실제 작품에 사용할 때는 반드시 원문에서 작성):
{ "schema_version": 2, "records": [{ "id":"R0001", "category":"character", "subject":"주요 인물명", "title":"현재 드러난 목표", "text":"그 시점까지의 행동에 기반한 목표 설명", "confidence":"strong_inference", "evidence":"원문에서 복사한 정확한 근거 구절", "reveal":{"quote":"공개 시점에 해당하는 실제 원문 20자 이상의 구절","occurrence":1}, "replaces":null, "story_order":null }] }

## 엄격한 위치 및 스포일러 검증
- 모든 evidence와 reveal.quote는 원문에 실제로 있어야 한다. 공백을 포함한 글자가 다르면 무효다. 추측으로 원문 인용문을 만들지 않는다.
- 해당 reveal.quote의 지정된 번째 출현 위치까지에서 evidence를 찾아야 한다. evidence가 그 이후에만 있으면 공개 위치를 더 뒤로 옮긴다.
- 나중에 밝혀지는 인물의 정체·목표·관계·사건은 먼저 공개하지 않는다.
- replaces는 항상 먼저 공개된 기존 기록만 가리킨다.
- 작성 후 본문과 JSON을 다시 분리해 JSON 구문, id 중복, 위치 확인, 근거 선후관계, 스포일러 여부를 검사한다. 검증되지 않은 레코드는 완성본에 넣지 않는다.
- 기록이 전혀 없으면 억지로 만들어 채우지 않는다.

## 진행 및 납품
장편은 구간별 중간 결과를 저장하고 완료 후 통합해도 된다. 처음에는 분석 구간 계획과 공개 위치 검증 방식을 제시한다. 원문을 파일 바이트로 읽고 쓸 수 있으면 최종 결과는 **통합 TXT 하나**다. 프로젝트 환경에서 원본 파일에 프로그래밍 방식으로 덧붙일 수 없으면 원문을 재생성한 통합본을 거짓으로 만들지 말고 **검증된 JSON만 제공**한다. 이후 tools/pack-reader-insights-v2.py로 원본 TXT와 JSON을 합치면 된다. 원문을 수정하거나 요약본으로 대체하지 않는다.

## 장편소설 내비게이터용 추가 메타데이터 (기존 v2 JSON과 호환)
아래 항목은 레코드마다 선택적으로 작성하되 **정보가 해당 독서 지점까지 드러난 경우에만** 추가한다. 전체 작품의 진실을 안다는 이유로 앞부분 기록에 미래의 별칭·관계·장소·해석을 포함하면 안 된다.

- `entities`: 현재 구간까지 알려진 주요 인물·장소·사물과 레코드의 연결. 예: `[{"id":"person-eunseo","name":"은서","type":"person","aliases":["서 연구원"]},{"id":"object-silverkey","name":"은빛 열쇠","type":"object","aliases":[]}]`. 종류는 person/place/object/concept/other 중 하나. 동일 인물·사물은 일관된 id를 사용한다. 아직 드러나지 않은 정체를 연결하는 ID 또는 별칭은 금지.
- `aliases`: 레코드의 핵심 대상에 관해 그 시점까지 독자에게 알려진 호칭만 배열로 기재한다.
- `scene_id`: 해당 정보가 중요해지는 장면 ID. 장과 주요 사건을 혼합한 분석 구간에 고유 ID를 붙인다. 같은 장면의 서로 다른 기록은 동일한 scene_id를 사용한다.
- `related_ids`: 함께 확인하면 이해가 쉬워지는 다른 레코드의 id. 과거에 공개된 기록이 주 대상이며, 후속 기록으로의 링크는 해당 후속 기록이 독자에게 공개될 때까지 숨겨져야 한다. 연관성이 명확하지 않으면 빈 배열.
- `importance`: 1~5 사이 정수. 5는 핵심 갈등·목표·중요 전환점, 1은 가끔 참고할 만한 정보. 매번 5로 기록하지 말고 차등화한다.

이 필드는 독서정보를 **현재 장면 관련 기록·인물별 현재 상태·변화 이력·사건 지도·핵심 단서·검색**으로 탐색하기 위한 색인이다. 분석 내용은 독서정보의 네 범주(event, relation, character, clue)를 벗어나지 않는다. 단순히 검색어를 늘리려고 없는 관련 인물이나 근거 없는 관계를 추가하지 않는다.

독자의 현재 페이지와 연결하는 과정에서도 자료에 없는 의미를 자동으로 창작하지 않는다. 뷰어는 이미 공개된 기록의 명칭·별칭, 장면 ID, 본문 위치 등을 사용한 **색인 탐색**만 수행한다. 의미 이해를 위한 추가 AI 호출은 하지 않는다.

특히 다음 원칙을 지킨다.
1. 인물의 **현재 상태**는 그 시점까지 나타난 최신 판단이고, **변화 이력**은 이전에 공개된 레코드의 기록이다.
2. 메타데이터가 없으면 이전의 subject/category/title 값으로 최소한의 탐색만 제공한다. 알 수 없는 인물의 동일성은 추정해 합치지 않는다.
3. 해당 독서 지점까지 공개된 레코드만 검색/탐색 색인에 포함한다.
4. 공개 레코드가 하나도 없는 책은 빈 정보 패널을 유지한다.
